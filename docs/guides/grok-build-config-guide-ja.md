# Grok Build 設定の所有範囲

CC Switch は Grok Build のライブ `config.toml` を 2 つの所有レイヤーに分け、API プロバイダーを切り替えても無関係な設定を消さないようにします。

## プロバイダープロファイルとグローバル設定

Grok Build プロバイダーが所有するのは次の項目です。

- `endpoints.models_base_url`
- `models.default` と `models.web_search`
- `subagents` セクション全体
- 認証情報と独自フィールドを含む全 `model.*` プロファイル

それ以外の MCP、telemetry、harness、feature、UI、将来追加される未知のセクションは Grok インストール全体のグローバル設定です。インポートとライブからの書き戻しではプロバイダーレイヤーだけを抽出します。公式 OAuth に切り替えるとプロバイダーレイヤーだけが削除され、グローバル設定は残ります。

Grok Build プロバイダーフォームの **プロファイルをライブ設定に適用** は、現在の下書きをライブファイルへマージします。**グローバル config.toml を編集** はファイル全体と解決済みの実パスを表示します。

## パスの解決順序

最初に一致した場所を使います。

1. `GROK_CONFIG`：設定ファイルそのもののパス。
2. `GROK_HOME`：`config.toml` を含むディレクトリ。
3. CC Switch 設定に保存した Grok ディレクトリ。
4. 既定の `~/.grok/config.toml`。

相対環境パスは CC Switch プロセスの作業ディレクトリから解決されます。絶対パスを推奨します。環境変数変更後は CC Switch を再起動してください。

## バックアップとプライバシー下書き

既存ライブファイルを書き換える前に、以前の内容をローカル CC Switch 設定ディレクトリ内の `grok-config-backups` に保存します。同じ内容の書き込みでは重複を作らず、最新 10 件を保持します。API キーを含む場合があるため機密ファイルとして扱ってください。

復元時には現在のライブファイルを先にバックアップします。削除は選択したバックアップだけに作用します。

**プライバシー設定を下書きに追加** は telemetry、trace upload、codebase upload を無効にする変更をエディターへ入れるだけです。自動保存はしないため、TOML を確認してから明示的に保存してください。

## プロキシ引き継ぎ

Grok Build の引き継ぎは `models.default` だけでなく、すべての `model.*` を更新します。各プロファイルにローカルプロキシ URL、プレースホルダー認証情報、`api_backend = "responses"` を設定し、`endpoints.models_base_url` も更新します。モデル名、env_key、コンテキストウィンドウ、subagent 選択、未知の独自キーは保持されます。既定、Web 検索、サブエージェントの各モデルがプロキシを迂回できなくなります。
